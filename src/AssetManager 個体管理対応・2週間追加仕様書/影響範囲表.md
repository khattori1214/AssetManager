### 4.2 影響範囲表を作る

読んだ結果を、次の表にまとめてください。1行目は例として埋めてあります。

| 確認項目 | 現在の実装（ファイル・メソッド） | 個体管理後の変更 |
| --- | --- | --- |
| 貸出対象の識別 | `BorrowAssetRequest` の `asset_id` | `asset_item_id` に変わる |
| 貸出中の判定 | `LoanHistory`モデルの`isBorrowed`メソッド | 資産IDごとの管理から、個体IDごとの管理と未返却履歴を確認する判定へ変更 |
| 貸出履歴の参照先 | `AssetManagementContorller`のcurrentEmployeeLoans()メソッド、貸出履歴と個体を結合し、貸出履歴を参照 | asset.idの代わりに、asset_item_idを使い、貸出履歴の参照をできるようにする |
| 資産一覧の「貸出可/不可」表示 | assets_index.blade.php | 個体ごとに「貸出可/不可」表示できるように変更 |
| 利用履歴画面の資産名表示 | assets_index.blade.php  | 個体ごとに資産名表示できるように変更  |
| 管理者画面の全社員貸出状況 | admin_index.blade.php | どの個体を誰が借りているか表示できるよう変更 |
| 期限超過メールの資産名 | mail | ？ |
| 開発用シーダー | LoanHistorySeederのasset_id | asset_item_idを使い個体管理できるよう変更 |
| 消耗品の取得 | AssetApplicationControllerのdecreaseStockメソッド | 変更しない（ただし既存不具合を修正） |
| 修理中・廃棄の表現 | 未対応 | 個体の状態として追加 |

**ヒント**：`loan_histories.asset_id` を使っている箇所は、すべて影響を受けます。`asset_id` で全文検索し、`loan_histories` と組み合わせて使っている箇所を洗い出してください。JOIN の条件に書かれているものも見落とさないようにしましょう。

この表は、後で「既存機能が回帰していないか」を確認するときのチェックリストにもなります。
